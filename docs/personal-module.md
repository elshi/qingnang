# “我的”模块
实现位置：`miniprogram/pages/profile`、`favorites`、`notes`、`history`、`feedback`。

## 功能
- “经典 / 我的”双标签；“我的”进入收藏、笔记、历史记录、意见反馈和隐私说明。
- 医书（整书与章节）、医案、处方、经络、穴位收藏；关键词搜索、类型筛选、取消收藏。
- 自由笔记与关联原文笔记，新建、编辑、删除、搜索、分类、自动草稿恢复；原文可点击返回。
- 语音按钮录制最长60秒的音频附件，可回放和移除，不声称自动转写。
- 最近200条浏览记录，按日期分组；医书恢复章节、内容模式和滚动位置；清空需要确认。
- 反馈类型、内容和联系方式校验，最多3张5MB以内的截图，上传成功并得到服务端确认后才显示提交成功。

## 云端部署（上线前必做）
阅读内容仍使用原有 Laravel 云托管 API；个人记录使用项目已有的微信云开发环境，无须新增 AppSecret。
1. 核对 `miniprogram/app.js` 中 `cloudEnvId` 是本小程序已关联且可用的环境（目前与内容 API 的云托管环境不同，应保留区分）。
2. 在该环境创建 `personal_records`、`personal_feedback` 集合。两个集合均设置为客户端不可读、不可写，只允许云函数访问，参考 `cloudfunctions/personal/database.rules.json`。
3. 为 `personal_records` 建立 `owner ASC, _id ASC` 组合索引。
4. 云存储设置为“仅创建者可读写”，禁止公开读取个人附件。云函数与客户端必须使用同一个云环境。附件路径为 `personal/{账号哈希}/voice/` 或 `feedback/`。
5. 在微信开发者工具中，右键 `cloudfunctions/personal` → 上传并部署（云端安装依赖）。云函数使用微信可信上下文识别用户，不接受客户端传入的 openid；同步接口同时校验当前账号。
6. 在小程序管理后台补充实际运营主体的隐私保护指引，声明录音与选取图片用途。页面内的说明反映实现行为，不能替代平台要求的主体信息。
7. 真机验证登录、两台设备同步、离线恢复、录音权限拒绝和截图上传。反馈在云数据库 `personal_feedback` 中处理。

函数未部署时，本机收藏、笔记、草稿、历史记录可用；登录或反馈会显示真实失败状态，不会模拟登录或提交成功。此次代码变更不自动发布生产环境。

## 数据与恢复
本机命名空间为 `qingnang.learning.v1:`，访客与每个登录账号隔离。首次登录后把访客记录合并进该账号；旧 `noteDraft` 会作为自由笔记草稿恢复。
写入先持久化本机，再同步；同步失败保留待发送队列。同步按记录时间合并，删除使用墓碑避免旧设备复活已删除条目。草稿不上传。音频首次同步时上传，失败不清除本机草稿或待同步记录。
清空历史不删除收藏或笔记；原有医书阅读偏好与最近阅读进度仍保留。笔记编辑中返回自动保存草稿。
不提供自动转写、头像昵称获取或账号注销的自助界面；账号数据请求通过反馈处理。

## 验证
运行 `node --test tests/miniprogram/*.test.cjs`。小程序的 WXML/WXSS 与实际屏幕通过微信开发者工具验证；详见 `design-qa.md`。

当前结果：36 项测试通过，23 个 WXML 和 28 个 WXSS 文件编译通过。六页对照图见 [验收截图](screenshots/personal/comparison-final.jpg)。

原生自动化脚本为 `scripts/verify_personal_ui.cjs`，需要安装 `miniprogram-automator`，并让 `NODE_PATH` 指向对应的 `node_modules`。在独立小程序副本启用开发者工具自动化端口 9421 后运行；脚本会临时装入验收数据并在结束时恢复。可设置 `PERSONAL_QA_ENDPOINT` 指定端口，设置 `PERSONAL_QA_CAPTURE_ONLY=1` 只重拍截图。不要对生产设备运行验收脚本。
